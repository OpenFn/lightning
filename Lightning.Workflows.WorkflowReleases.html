    Lightning.Workflows.WorkflowReleases (Lightning v2.19.0)

    View Source

    Records and reads Lightning.Workflows.WorkflowRelease rows.

    A release is recorded at each go-live and promote, in the same transaction as the snapshot it points at, and numbered max(existing) + 1 per workflow.

    That numbering is safe only because callers record a release exclusively when the save captured a snapshot: capturing one updates the workflow row, so the optimistic lock serialises concurrent publishes. The (workflow_id, version_number) unique index is the backstop.

    Fetches the release published as version_number for the workflow, preloaded with its snapshot so the caller can resolve the pinned content.

    version_number is the human version the UI shows as vN and the value ?release= carries. Returns nil when the workflow has no release with that number (a hand-typed number, or an old lock_version that was never published).

    @spec version_numbers_by_lock_version(
  Lightning.Workflows.Workflow.t()
  | Ecto.UUID.t()

    Maps each released snapshot lock_version to the version_number it was published as.

    This is what attributes a run to a release: a run carries its snapshot's lock_version, and Map.get/2 gives nil for one that was never released. Where two releases share a lock_version the newest wins.
